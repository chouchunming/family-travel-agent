# Evidence and Needs Discovery

## Standalone evidence

Use user text, files, confirmations, and URLs. Rank current official booking
evidence first, then an official venue or public body, established map provider,
and labeled secondary source.

## Optional LLMWiki discovery

Activate only after mode detection succeeds. Read the installed `llmwiki`
skill and repository rules. Search compiled summaries and concepts first, then
canonical task records. Read relevant observation records for workflow friction
and immutable session evidence only when compiled state is insufficient or an
inferred need needs support.

Classify each need as already supported, trip-specific data, a reusable workflow gap,
a one-off open loop, or outdated and superseded behavior. Present evidence
before expanding the skill. Prefer repeated needs, costly errors, safety issues,
and reusable formats.

Observation records describe process and do not count as compiled source coverage.
Never edit immutable session evidence. For an authorized Wiki write, edit the
smallest compiled page or canonical task, preserve unrelated changes, follow
observation rules, and run the repository's validation.
